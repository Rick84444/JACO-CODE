# Evidence-grounded procedural memory for Aura
Research dossier, 2026-11-18. Source audit at JACO main 15ffaa332f872e98561467c868bbb77ee78c27d1. This is an engineering research synthesis, not peer-reviewed JACO results. The scope is existing RobotMower, Laser Vision, DOM Traction, SkillRuntime and Continuum. No second runtime, agent, tool registry, browser controller or memory store.

## Research question and prior art
Can one agent amortize repeated GUI exploration through evidence-grounded procedure reuse, without increasing wrong-object actions or total inference cost? Hypothesis H1: bounded semantic route recall plus existing skill compilation reduces repeated work. H0: against a token-matched reactive baseline, the benefit disappears or correctness worsens. H2: combining current DOM/accessibility with localized visual evidence improves recovery. H3: failed traces help avoid recurring errors, only when the failure and subsequent correction are actually observed.

Primary sources (reviewed public abstracts/project pages; not independently reproduced):
- Wang, Mao, Fried, Neubig, Agent Workflow Memory, ICML 2025: https://proceedings.mlr.press/v267/wang25bx.html . Reports +24.6% and +51.1% relative success on Mind2Web and WebArena. Text workflows induced from trajectories, not generic verified execution.
- Wang et al., Inducing Programmatic Skills for Agentic Tasks, COLM 2025: https://arxiv.org/abs/2504.06821 . Reports +23.5% relative success over static agent and +11.3% over text skills on WebArena; programmatic verification matters.
- Zhong et al., ActionEngine, Feb 2026 preprint: https://arxiv.org/abs/2602.20502 ; https://www.microsoft.com/en-us/research/publication/actionengine-from-reactive-to-programmatic-gui-agents-via-state-machine-memory/ . Closest prior art: offline GUI exploration builds state-machine memory, programmatic execution and localized vision fallback. Reddit subset of WebArena: 95% vs 66% success, mean approximately one online LLM call, 11.8x lower reported cost, 2x latency improvement. Include offline mapping/repair cost and do not generalize to all desktop tasks.
- Graph-Structured Persistent Memory for Efficient LLM-Based Computer Use Agents, June 2026: https://www.mdpi.com/2075-1680/15/6/415 . Reports roughly 50% reductions in model tokens and execution time with comparable OSWorld success in its configuration. Related graph-memory architecture; does not establish JACO novelty.
- Hajimiri et al., Are Online Skill and Memory Modules Always Worth Their Tokens?, EMNLP 2026: https://aclanthology.org/2026.emnlp-main.1657/ ; https://sinahmr.github.io/budget-constrained-web-agents/ . Across four WebArena domains and three models, token-matched vanilla actor matches or beats AWM/ASI/ReasoningBank aggregate success, often with fewer tokens. WorkArena-L1 shows similar trend. This is the key counterhypothesis: memory must earn its budget.
- Ouyang et al., ReasoningBank, ICLR 2026: https://arxiv.org/abs/2509.25140 ; https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/ . Extract transferable strategies from both successful and failed traces; avoid unverified self-judgment as production proof.
- Zheng et al., SeeAct, ICML 2024: https://arxiv.org/abs/2401.01614 . Hybrid HTML + visual grounding. Use DOM/AX candidate reduction before screenshot inference.
- Xie et al., Jedi / OSWorld-G, NeurIPS 2025: https://osworld-grounding.github.io/ . UI decomposition; 564 grounding benchmark samples. Reports 23% to 51% OSWorld improvement with learned grounding in study configuration. Visual grounding can help desktop tasks, not automatically the web bottleneck.
- Shlomov et al., From Grounding to Planning: Benchmarking Bottlenecks in Web Agents: https://doi.org/10.3233/FAIA251390 . Controlled web planning/grounding study suggests planning is primary bottleneck in that dataset. Measure separately rather than improve vision blindly.
- MementoGUI, May 2026 preprint: https://arxiv.org/abs/2605.18652 . Select localized visual evidence, compress working memory, retrieve relevant episodes; proposed controller involves training, not suitable for immediate wholesale reuse.
- Voyager: https://arxiv.org/abs/2305.16291 . Executable skills and environment feedback in Minecraft, useful design analogy, not proof of desktop transfer.
- Efficient GUI Agents systems survey, Sep 2026 preprint: https://arxiv.org/abs/2609.02309 . Observation, memory, runtime and verification cost need joint accounting.
- LLM Self-Healing of Web Locators as Assisted Triage, Oct 2026: https://doi.org/10.1016/j.jss.2026.113157 . Adversarial identity oracle on 133 broken selectors: recovery reported 55-68%, roughly a quarter wrong-element resolutions. Never equate successful selector resolution with correct target identity.

## JACO source findings and integration
- SurveyLibrary (runtime/src/server/handsOff/surveyLibrary.ts) already stores bounded structural and semantic surveys, actionable routes, confirmation/loss and drift metrics. It currently treats a missing semantic signature as matching, and historical name matches are broader than object identity. Historical routes are candidates, not authority. Inspect all callers before tightening reuse.
- PR #303 (fe151ff) adds current mission-bound screen frames and CDP target re-identification; reviewed as separate branch work, not assumed merged. DOM Traction needs current identity in the true actuator; desktop focus-bound physical input remains unvalidated.
- agents/lib/adaptive-perception.mjs already owns ROI selection. Prefer a bounded DOM/AX read; use ROI only for the relevant screen and full frame when necessary, with existing cloud-image consent.
- agents/lib/effect-evidence.mjs and living-core-promotion.mjs distinguish historical observations and independent effect verification. Never promote a mutation's own self-attestation. 
- agents/lib/skill-learning.mjs learns correction notes and procedural candidates from receipts. Its former positive correction predicate was ok-only; unknown outcome and dispatch-only observations could enter learning. This change excludes these from the candidate path and keeps the existing approval flow.
- ContinuumRuntime owns SkillRuntime. skillIR, skillCompiler, targetCompiler, skillMachine, executionProfiler, traceNormalizer, proceduralFamilyMiner, processVerifier, benchmarkArena and adaptiveSkillOptimizer already provide a typed procedural/optimization pipeline. Extend them, do not create another compiler/database. The canonical evidence validator exists, but provenance must be tied to the exact expected outcome, not arbitrary verified evidence refs or self-assigned flags.
- Current shape signatures abstract values; distinct meanings can collide in a family. Current survey process/name and receipt-only matching are insufficient to establish semantic equivalence across tasks. Retain exact goal/target family, parameters, current contract scope, versioned preconditions and independent oracles. Trace duplicate protection and negative memory tests required before automated promotion.

## Proposed staged path
A. Harden learned-memory admission and evidence ownership first (this PR). Keep failed outcomes diagnostic; do not infer successful corrections from unknown writes, transport ack or dispatch only. Preserve legacy approval requirements.
B. Bind RobotMower route candidates to current origin/app, role/name, ancestor or stable identity where available, current session and semantic signature. Use current observation to resolve, reject ambiguity, and collect actual before/after receipts. Store stable semantic descriptors rather than coordinates, personal field values, screenshots or raw credentials.
C. Convert verified repeated traces through existing SkillIR (OBSERVE, LOCATE, ACTIVATE, WRITE, ASSERT, RECOVER, RETURN). Parameterize inputs and scope, avoid hardcoded stale selectors. Run through the existing mission/contract execution lane, never bypass tool permissions. Reuse exact-step plan only where preconditions hold. Invalidate or quarantine drift, fall back to ordinary planning, propose repaired skill as a new candidate.
D. Use same knowledge store and current skill lifecycle. Keep empirical counters for successful, rejected, uncertain, reidentified and recovery attempts, with source evidence. No automatic publication or authority upgrade from a learned route.
E. Validate on held-out tasks and model swaps. If evidence cannot support the benefit, revert to baseline. Idle observation must not disrupt active missions.

## Predeclared experiment (not yet run)
Primary endpoint: independent task success, including correct target and requested durable outcome. Main efficiency endpoint: total input/output tokens per successful task, including exploration, memory induction, retrieval, repair, failed tasks and verification, plus amortized cost for repeat count N. Secondary: wrong-target actions, unknown effects, UI recovery, total wall time, p50/p95 latency, token/call breakdown, CPU/RAM, privacy egress. Model/price/host/version held fixed per paired comparison. No remote fees without explicit operator budget. 
Arms: A existing reactive baseline; B token-matched reactive baseline (more steps); C current semantic DOM tracking; D C + bounded route/skill recall; E D + ROI fallback. New and repeated tasks separated. Suggested initial controlled study: 20 task templates x 5 independently seeded runs per arm; include changed DOM position, duplicate labels, reused IDs, stale tab, blocked inputs, partial dispatch, timeout, changed expected outcome, and no-benefit cases. Use local fixture browser and deterministic independent server/DOM state oracle; hold out at least 5 task templates from induction. External follow-up WebArena/OSWorld/MemGUI-Bench, then real Windows/Pixel device.
Provisional engineering acceptance (not results): zero observed wrong-target or duplicated mutations on adversarial negatives, no more than 2 percentage-point success degradation against matched baseline, >=25% lower median total tokens per successful repeated task with correct accounting, report paired bootstrap confidence intervals and all failures. Zero observed failures not proof of zero risk. Report sample size and exact CI/revision. Do not promote if evidence insufficient; use ordinary planner. No new gate on unrelated missions.
