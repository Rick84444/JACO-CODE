# Align Lite and full JACO release and autonomous project execution

## Why
Lite and full JACO can ship different source revisions because their release workflows watch different path sets. Lite also overrides the canonical project contract and freezes the available tool list; it can require a full repository test suite for a new document or prototype which full JACO deliberately does not. Nova stops on three consecutive diverse failures regardless of a larger operator contract failure budget. The Core approval tick polls slowly and a missing independent provider can delay otherwise verifiable results.

## What changes
- Build both release families for the same product-relevant main changes; embed the exact source commit in full Windows payload and manifest, retaining platform-specific packaging.
- Use the same project contract and test discovery rules in both paths. Keep read-only and no-network restrictions and give Lite its existing safe project tools including read-only MCP.
- Respect the contracted consecutive-failure allowance, while retaining the deterministic same-action and unknown-outcome stops.
- Bound completion claim-check provider latency and speed up the existing auto-approval tick. Do not approve a contradicted or unsupported answer.

## Falsifiers
A product change triggers only one artifact; a full installer lacks commit identity; a Lite read-only mission can write; a new HTML demo inherits unrelated npm test; an unknown-outcome action resumes; a contracted budget is exceeded; or an unsupported claim is auto-approved. Any is a regression. No deployment or new outgoing financial authority is granted.
