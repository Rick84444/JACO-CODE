# Design

Official Linear docs https://linear.app/docs/mcp specify interactive DCR and read scope on /mcp. Observed https://mcp.linear.app/.well-known/oauth-authorization-server advertises same-origin issuer, authorize, token, register, S256, public client auth none, issuer response and CIMD. Protected-resource metadata not retrieved by research tool; runtime must verify exact resource and issuer before registration. For this first provider only, all outbound URLs are pinned; no redirects, arbitrary discovery or token audience switching. Use DCR as documented provider compatibility mechanism, no assumption of generic MCP 2026 compliance; CIMD remains preferred for general support. Random loopback callback, one-time state and PKCE, issuer response check, scope read only, expiry, no scope escalation. Verify actual list_teams response before saving scoped credential envelope; only read tools are advertised or dispatched, and provider token itself has read scope. Store access/optional refresh tokens and registration in existing encrypted vault as one scoped record; refresh before expiry under in-process singleflight and vault compare-and-set, never replay a tool call on authorization loss. Reauthentication and local disconnect are explicit; remote revocation not assumed. No tokens in response, browser storage or logs. First implementation deliberately blocks when provider metadata or schema differs. Preserve existing Linear configuration via a separate connector ID. Research sources: https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization ; https://linear.app/changelog/2026-09-14-loops-for-product-management .
