# Ice cavern presence mode
Extend the canonical Aura portrait and existing CC0 rig, preserving the original close-up and separate optional photoreal head. The operator-approved reference is a deep, near-black icy cavern with cyan crystals, reflective ice floor, dark distance and a modestly clothed tall figure. The current rig is not the approved face; do not claim identity fidelity. No image copied into the runtime. No new dependency, inference, API, permission, renderer or mission authority.

## Design and acceptance
Use deterministic low-poly world-space cave walls, instanced crystals, fog, floor and static lights in the same Three.js scene. Camera parallax is geometric; floor glints are an approximation, not a reflected live avatar. Frame the existing clothed skinned rig in full, with bounded head, shoulders, spine, pelvis and arm motion when bones exist. Use the existing facial morphs, with teeth/tongue from the verified source where present. Never paste a mouth texture or claim phoneme alignment from formants. When there is no observed audio in cavern mode, keep the mouth neutral instead of inventing syllables. Keep microphone and playback paths unchanged. Use only a single renderer; stop hidden animation; reduced motion uses static frames. GPU skinning for visible body, no CPU per-point deformation in cavern mode. Budget 15–24 FPS, low pixel ratio and adaptive frame cadence when measured render cost exceeds budget or a mission is active. No dynamic shadows, postprocessing, ray tracing or second render pass. No automatic external model acquisition. UI shows actual errors.

## Verification protocol
Baseline existing portrait vs cavern mode on matched desktop and mobile utterances and a concurrent mission. Record actual screen capture, draw calls, geometry counts, CPU/GPU memory where observable, median and p95 frame time, audio timing, long tasks and mission latency. Target median >= 20 FPS on desktop, >= 15 mobile; p95 <= 67 ms, mission throughput degradation <= 5%, no unrequested permissions or duplicate audio, no clipping of shoes/head at tested sizes, no detached mouth. Negative controls: hidden tab, reduced motion, missing clothing geometry, unsupported renderer, sustained slow frames. Exact-head browser CI and visual approval required before merge; these are targets not measured results.
