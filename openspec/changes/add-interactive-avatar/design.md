## Adaptive workspace
Existing owner JacoAuraComputeIDE delegates layout to CognitiveWorkspace and already has human/raw terminal, /api/terminal/exec, tool selection, ConnectionsWorkspace, ProviderConnect and CDP selection. Extend these owners instead of duplicating. Evaluate xterm.js (MIT; https://github.com/xtermjs/xterm.js) for ANSI rendering, fit and bounded scrollback; preserve existing command authorization, no new unrestricted PTY endpoint. Evaluate dockview-react MIT core (https://github.com/dockview/dockview) for desktop right-hand panels only if the existing layout cannot meet requirements; mobile uses responsive single active detail. Route typed presentation requests via existing authenticated transport and resolve registered tool/provider/target IDs, not arbitrary component names. Reuse CDP target for live browser preview; evaluate screencast bandwidth and input controls. Electron WebContentsView is optional only if it does not duplicate browser ownership; sandbox, context isolation, no Node integration for remote content. Respect frame-ancestors and X-Frame-Options; use external navigation fallback. No credentials in panel state. Visual acceptance requires real desktop and mobile screenshots and operator review before replacing existing default.

## Existing implementation constraints (source inspection)
CognitiveWorkspace already implements conversation/detail layout, pinned work, desktop shortcuts, remote session revalidation and separate mobile focus. Extend this component; do not introduce a second shell. VoiceChannel is the WhatsApp linking UI, not a browser speech engine; trace existing audio APIs before selecting a speech adapter. cognitiveEvents.mjs normalizes runtime observations, filters noise, redacts secrets and distinguishes observed from verified outcomes. Drive presentation from this contract; never pass raw payloads to avatar speech or generative components. Preserve operator pinning, chat input, remote session authentication and existing approval/cost boundaries. Prefer existing layout over Dockview unless measured requirements demonstrate a gap. Android acceptance requires real Chrome playback, touch navigation, reconnect, reduced motion and frame-time measurements. No browser speech-synthesis substitution for accepted neural speech. No procedural oval substitution for accepted rigged mesh. Check actual dependency licenses and asset distribution before installation. Production integration remains pending build and device evidence.
