## Aura Desktop end-to-end closure: session-bound human takeover

The one and only Aura control plane remains `NovaMissionControl`/ModelRelay. The operator's Chrome Remote Desktop window is merely a viewing and manual-input surface attached to the same Windows interactive guest session; neither Chrome Remote Desktop nor VMConnect authorizes or dispatches model actions. JACO's `AuraDesktopMonitor` is a still-image view, not a remote-video transport.

A pause is **cooperative**, not a lock. The mission may hold a live planning lease even if no semantic UIA call is currently active. The read-only `executionLeaseActive` property of the existing `NovaMissionControl.get()` projection is true when any Nova lease owner, token or unexpired deadline is present; its sensitive token/owner must never be returned. The `desktopTakeoverState` projection returns ready only when (1) the exact desktop mission is ACTIVE, (2) an operator pause is present, (3) `executionLeaseActive === false` (unknown must deny), (4) mission phase READY with no active task/cancel request, (5) the shared UIA client is not busy and (6) the ModelRelay desktop actuator lease is empty. This is a **JACO quiescence observation**, not a guarantee that the external remote viewer shares the same session or that another third-party process cannot move the cursor. Stop or pause before manual takeover; after manual action require fresh screenshot/UIA observation on resume.

Acceptance distinguishes three levels:
1. Static/CI: APIs, types, PowerShell syntax, mocked policy/model tests and no bypass paths.
2. Windows integration: real Win32 screenshot and SendInput, real UIA readback, signed mandate/lease receipts, locked-session refusals and real Windows profile/runtime startup.
3. Operator acceptance: a licensed isolated Hyper-V guest actually exists, Chrome Remote Desktop observes the same interactive session, Aura completes an independently verifiable Notepad save/readback mission, recovery and pause/takeover/resume are exercised, and receipts are retained without publishing private pixels/secrets.

The first level alone **must not** be described as production-ready. No CI runner proves Google login, guest isolation, same-session live cursor behavior or full end-to-end mission completion.
