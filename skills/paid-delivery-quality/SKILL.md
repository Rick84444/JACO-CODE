# Paid delivery quality

This procedure prepares and reviews a delivery. It is read-only in this catalog; actual coding, artifact writes, uploads and external submission require a separately authorized scoped mission and the existing tools. Aura owns the work. Never invent an assignment, deliverable or settlement receipt.

1. Read a current assigned/funded status from the original provider, scope, deadline, price, review process, AI permission, customer data classification and allowed tool/model providers. A public escrowed listing is not an exclusive paid assignment. Reject ambiguous scope or obligations; send a clarification draft instead of doing unpaid custom work.
2. Translate requirements into an acceptance matrix: requirement ID, observable pass criterion, oracle, input/sample, output path, test command or inspection method. Record constraints and excluded changes. Define rollback and time/cost cap before mutation. For research require primary sources, dates and claims; for automation test representative input, malformed input and repeat runs; for code reproduce defect, test fix and regression; for files verify openability and requested schema.
3. In a separately authorized private workspace, create the smallest deliverable that meets scope. Use local models/tools where authorized and avoid sending private customer files to unapproved providers. No public JACO commit of client material. Inspect third-party licensing and dependencies; pin versions. Never execute downloaded untrusted code outside the isolated contract. No new outgoing spend.
4. Independently review artifacts against the acceptance matrix. Include actual command, exit code, result and file digest where available, not model confidence. Re-run after any correction. If a required test cannot run, state limitation and hold external submission rather than falsify acceptance.
5. Prepare a delivery manifest with artifact filename, size, SHA256, requirements satisfied, install/run instructions, limitations and safe handover. Check for secrets, personal data, unrelated files and ownership rights. The operator must authorize the exact destination and payload before external delivery under the existing gate.
6. AgentGigs official documented worker endpoints are upload-deliverable and submit. The current JACO adapter is limited to discovery, application and quote; it does NOT expose those delivery writes. Prepare local handoff or use a separately authorized legitimate route; never route around a denied action through shell or raw HTTP. AgentGigs documents user approval followed by payout cooldown; check actual Stripe receipt before credit. Bounty documentation describes verification and Stripe settlement; no JACO write adapter exists. No auto-retry of ambiguous external submission. Reconcile by independent readback.
7. Record job ID, contract version, actual time and cost, acceptance result, revision requests, invoice/payment reference when available and separate provider/bank settlement observations. Store only non-sensitive evidence references in canonical mission and knowledge systems. An accepted deliverable or scheduled payout is not bank settlement. No refund or payment action in this skill.

Success: recipient accepts the scoped independently checked deliverable; mark paid only when payment is observed. If an approval or missing integration blocks submission, return the ready manifest and precise next action instead of looping.
