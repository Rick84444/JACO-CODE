    How it works

    1. Plan with your model. Ollama or LM Studio on your own machine, or a key for DeepSeek, Groq, OpenAI, Anthropic, Gemini, Mistral, xAI, Qwen, Together, OpenRouter or Hugging Face. JACO recognises the key, checks it, and keeps the model inside a contract: allowed tools, budgets, approvals.
    2. Act with real tools. Files, git, MCP servers and your own browser through CDP. Each step is a mission action with a lease, not a chat message.
    3. Prove it. Every action leaves a receipt. A separate model checks the final answer claim by claim against those receipts, and an answer that does not hold is sent back.

    Aura and the Gameboard

    Aura is the agent you talk to. Give her a goal, and the Gameboard shows how she means to reach it.

    The goal comes first

    Each plan is drawn like a family tree read backwards: the goal at the top, below it what is needed to reach it, and below each subgoal what that needs in turn. The subgoal she is working on glows blue. Click a box for the whole description and why it is there.

    Your yes, in one place

    What needs your approval is shown on the Gameboard where you see the plan, with a clear confirmation. When something carries a risk, Aura asks one plain question first: do you mean that I should do this and this? Payments always wait for you.

    Memory you can see

    When Aura saves what she found on a step, it shows in the chat and on its box in the Gameboard, so you and her helpers can read it later.

    One workspace, no tab hunting

    The chat is on the left and the work is on the right. There is one stage, and it decides for itself what deserves to be on it.

    1. The result, not the running commentary. When the agent writes a page, the stage renders it. When it drives your browser, the stage shows the screenshot. When a step is blocked, the blocker takes the stage ahead of the last thing that worked. Thirty identical file reads collapse into one line with a count.
    2. Only what is proven gets shown. A file becomes visible material only once its own receipt says verified and its path stays inside the project. An unverified or out-of-project path is never rendered, previews run in a sandboxed frame, and a screenshot older than thirty seconds is dropped rather than shown as current.
    3. Work, Evidence, Code, Preview. One click each, and the stage stays where you put it. On a phone the same views are a row of thumb-sized buttons instead of a tab bar.

    Pin the stage and it stops changing under you. Switch project and the captured page and screenshots are cleared, so you never see the previous project’s work framed as this one’s.

    JACO Lite

    The whole IDE and the Aura agent as one folder on your computer. Free. One command starts it, and nothing runs in our cloud.

    Your model, any model

    Paste an API key, or point it at Ollama or LM Studio on your machine. JACO finds out what it is and checks it. No account with us.

    An agent that has to prove it

    Give Aura a goal. It works on a separate git branch, never pushes or merges, and does not report done until your project’s own tests pass.

    Your code stays yours

    The server listens on your computer only, and keys are kept encrypted outside your project. Cloud models are on from the first start, inside a daily limit you can change in the budget panel; outgoing payments always stop and wait for you.

    One line, and it handles the rest

    The installer reads the checksum manifest over HTTPS, refuses any download whose SHA-256 does not match it, and installs Node.js itself if yours is older than 22.5 — checking that against nodejs.org’s own checksums. Nothing needs administrator rights, and nothing is placed outside the JACO folder and one command. There is no code-signing key yet, so the checksums protect against a corrupted or swapped file, not against this site itself.

    macOS, Linux, Android (Termux)curl -fsSL https://jacocode.com/install.sh | sh

    Windows (PowerShell)irm https://jacocode.com/install.ps1 | iex

    Then jaco-lite in any project folder starts it. jaco-lite update fetches the newest build, rollback returns to the previous one, doctor says what is installed and whether it can start, and uninstall removes it without touching your projects.

    Or take the folder yourself

    Download JACO Lite (zip, about 21 MB) SHA-256

    Built for one platform instead: Windows · Android. Every build and its checksum are listed in latest.json.

    1. Install Node.js 22.5 or newer if it is not already on your computer.
    2. On Windows, right-click jaco-lite.zip and choose Extract All. Open the extracted folder.
    3. Double-click START.cmd in that folder, or run node start.mjs from a terminal there.
    4. The connection guide opens automatically. Connect your model, optionally configure Codex, Claude Code or VS Code, and test the JACO Editor tool.

    Extract the whole ZIP before starting. Running START.cmd inside the ZIP only unpacks the launcher, leaving the application files behind.

    Every build is unpacked and started before it is published: the IDE answers, its live event stream runs, and the bundled tools load, on Linux and on Windows. The one-line installers are installed, updated and uninstalled in the same run. The Android build is made the same way from the same code and has not been run on a phone.

    JACO in VS Code

    If you already live in VS Code, the extension opens the same JACO IDE in an editor tab. It is the one you installed, not a copy of it.

    The same runtime

    No second agent, no second mission store, no second credential store. Chat, missions, Git and MCP stay owned by the JACO Core already running on your machine.

    Framing stays locked down

    JACO refuses to be framed by default. The extension does not strip that. JACO Lite turns on one narrow exception, for requests from your own computer and from VS Code’s own windows only, and the extension checks the runtime’s identity before it draws anything. From a Git checkout you switch it on with JACO_VSCODE_EMBED=1.

    Four commands

    Open Full IDE, Start Runtime, Open Terminal IDE and Open in External Browser, plus a JACO view in the activity bar.

    Get it on the VS Code Marketplace Read the extension source

    Or search JACO Cognitive IDE in the Extensions view. VS Code 1.96 or newer, desktop, with JACO Lite or a JACO checkout running locally. If JACO Lite had to pick another port than 3000, the extension finds it by itself; Start Runtime starts jaco-lite when no checkout is open. The extension itself needs no npm packages.

    Scope of this first release: desktop VS Code with a local Core. VS Code Remote, SSH, Codespaces, browser-based VS Code and remote JACO hosts are not claimed to work.
