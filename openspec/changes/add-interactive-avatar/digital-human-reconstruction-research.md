# Aura digital human: reconstruction research and acceptance gates
Date: 2026-11-26. Operator direction: retain the approved photographic character (long platinum hair, pale skin, blue-green eyes, modest silver technical suit with cyan seams, full body); defer ice cavern; dark neutral background; local runtime with no subscription, minimal competition with inference. This document proposes experiments, not shipped capabilities.

## Observed baseline
The separate locally generated Aura-photo-prototype.glb was inspected: 65,274 vertices, 130,544 triangles, one watertight connected mesh, POSITION/NORMAL/COLOR_0, zero textures, skins, morph targets and animations. Approximate dimensions 0.839 x 1.801 x 0.250 m. The builder extracts front silhouette, assigns heuristic cross-section depth, and projects front/back colors to vertices. Four-angle rendering exhibits smeared side textures, fused hair/shoulders, and flattened facial shape. It is not a production rig, and the original photo and mesh are not yet committed. Existing pinned CC0 MPFB rig has known facial morphs but does not match approved character. Keep as reference anatomy and fallback. Never pass a photo/depth estimate as a scanned human.

## Candidate routes and licenses
- A: Microsoft TRELLIS.2, 4B image-to-3D mesh with PBR, MIT code and weights; separate licenses for rendering dependencies, audit before commercial use. Source https://github.com/microsoft/TRELLIS.2 and https://huggingface.co/microsoft/TRELLIS.2-4B. Run only offline asset build on adequate hardware; no runtime diffusion. Upstream benchmark is H100, not operator machine. Generated anatomy, pose and facial topology require validation/retopology.
- B: fit MPFB CC0 core base mesh to approved silhouette/landmarks using Blender offline; build suit and hair separately; project consistent images to UVs, bake PBR and normal maps; preserve facial morph semantics. GPL authoring tool is separate from runtime; verify third-party assets individually. https://github.com/makehumancommunity/mpfb2/blob/master/LICENSE.md. Most controllable commercial baseline, no claim of perfect likeness.
- C: TripoSR alternative fast shape reconstruction (~6 GB VRAM reported upstream, MIT code and weights), evaluate against A, does not create facial rig. https://github.com/VAST-AI-Research/TripoSR. UniRig automatic skeleton and skin weights is optional offline candidate with MIT model card; verify dependencies and actual weight quality. https://github.com/VAST-AI-Research/UniRig and https://huggingface.co/VAST-AI/UniRig. Automatic body rigging does not create usable expression morphs by itself.
- D: LHM research comparator only: human-specific Gaussian avatar; model card expressly CC BY-NC 4.0, research only. Do not generate shipping assets from these weights absent rights clearance. https://github.com/aigc3d/LHM/blob/main/modelcard.md. AdaHuman (https://nvlabs.github.io/AdaHuman/) and AniGen (https://github.com/VAST-AI-Research/AniGen) are research leads, not approved for distribution; separate dependencies/weights require review.
- Animation: Mesh2Motion official code MIT and assets CC0 (https://github.com/Mesh2Motion/mesh2motion-app and https://github.com/Mesh2Motion/mesh2motion-assets). Retarget existing clips and inspect foot/hand contact. Rhubarb provides offline timed mouth cues from audio, phonetic mode for non-English (https://github.com/DanielSWolf/rhubarb-lip-sync); benchmark Swedish and English, no assumption of streaming or accurate phonemes. Prefer provider-supplied timed phonemes when present, use actual playback clock, and mark fallback as approximate.
- Runtime: Three.js GLTFLoader supports compressed mesh/textures with appropriate decoders (https://threejs.org/docs/pages/GLTFLoader.html). Asset creation is separate from presentation. No new agents, microphone permissions or external requests. Existing runtime handles audio and mission state; no per-frame model inference.

## Proposed experiment
1. Freeze selected reference and rights/provenance; create neutral same-pose side and oblique views, check silhouette, landmarks, camera scale and costume consistency. Synthetic views are hypotheses, not calibrated photographs. Do not force inconsistent images into photogrammetry. Keep expression and motion refs separate from geometry refs.
2. Compare A/C generated mesh candidates and B fitted canonical mesh. Render fixed front/45/90/back views and held-out reference angles, reject distorted anatomy or seam smearing. Use coherent UV projection, remove baked illumination, bake high-detail textures to lower-resolution mesh. Hair cards or strand ribbons with limited bones; separated eyes, teeth, tongue, hair, cloth, shoes; continuous face and neck. Avoid isolated mouth overlays. Retopology around jaw/eyes/shoulders/hips; inspect skin weights and expression shapes. Do not ship existing silhouette extrusion as a human model.
3. Build single body/head rig with morph targets for lips, jaw, cheek, blink, brow, gaze; authored and tested bilabial, vowels and silence. Body gestures are blended clips with independent idle breathing and foot-contact IK as needed; use playback timestamps, not fabricated speech cadence.
4. Export local GLB with asset version, SHA-256, license manifest, valid normalized joint weights, texture dimensions, real clips and required face morph list. No CDN. Preserve optional original rig and report missing asset explicitly. Use compressed textures and geometry, adaptive cadence/pixel ratio, stop hidden frames, release resources. Aim 30-60k body triangles in high mode, lower LOD when distant, 2K textures selectively, cap visual VRAM at 256 MB where measurable. No claim these are measured or universally feasible.
5. Controlled benchmark on actual Windows and Android (not just viewport emulator). Compare task completion rate/latency and local model throughput with renderer off/on, same inputs and hardware; >=15 FPS mobile, >=24 desktop median, p95 frame time <=67 ms on each where possible; model throughput loss <=5%; record draw calls, long tasks and memory where supported. Test hidden tab/reduced motion, unsupported GPU and no additional audio or permission. Keep raw screenshots and recordings including close-up and full body. 20 held-out Swedish/English utterances, audio/visual timing target <=150 ms absolute offset, no visible disconnected jaw, 10-minute animation stability. Quality targets subject to operator acceptance, not current results.
6. Visual acceptance proposed weighted score: face likeness 30%, mouth and facial motion 25%, body motion 20%, clothing/hair 15%, multi-view coherence 10%. Operator independently rates each 0-10 against approved image, target >=8 overall and no critical region below 7; mandatory performance and rights gates independent of score. Compare actual render not concept art. No default replacement or merge until evidence and applicable CI pass.

## Current decision
Prefer a conventional textured rig for runtime, with offline reconstruction-assisted asset authoring. Compare alternatives rather than commit to a specific generation model before hardware capability and licensing are established. No heavy model has been run in this research step; no new model or paid compute provisioned.
