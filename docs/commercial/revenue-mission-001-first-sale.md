# Revenue Mission 001 — first-sale experiment (2026-11-08)

**Owner:** Aura (the only primary agent). **Canonical charter:** [#68](https://github.com/Rick84444/JACO-CODE/issues/68). This is a commercial **experiment**, not evidence that Aura has been activated or that a customer bought anything.

## Two complementary business engines
1. **JACO Web Operations** — paid outcomes for small Swedish service businesses. Initial ICP: owner-operated service companies with an existing website and one explicit, observable problem.
2. **JACO CODE** — product usability validation in parallel: one installation and one real Aura task from start to independently observed receipt, then 10 qualified external testers (target, not observed).

## First customer offer (HYPOTHESIS — not an approved public price)
- **One scoped improvement:** SEK **4,900 ex VAT**, written scope, baseline, one change, relevant tests and a human-readable before/after report.
- **Optional upkeep:** SEK **990/month ex VAT**, exactly specified monitoring and reporting frequency; no unlimited support or implied autonomous access.
- **Promise only controllable outcomes:** accepted scope and independently testable delivery. No promised SEO ranking, leads, revenue or uptime.
- **CTA:** ask a business owner to describe one website problem; no binding contract or payment through the prototype.
- **Excluded:** unsolicited mass mailing; access to client systems without explicit permission; unaudited production publish; security guarantees.

## Sequence: execute through existing capabilities, no duplicate revenue engine
1. **Gate 0 / reality:** Observe installed Windows build SHA, authenticated Aura/mission control, model budget, Core, Workplace, browser/CDP and state continuity. Do not report the mission RUNNING on a GitHub issue alone. Reuse Continuum `RevenueOpportunityEngine` and `EconomicGovernor`; never create a separate agent, CRM, ledger or scheduler.
2. **Demand:** Collect 10 dated public demand observations with URLs, evidence, problem description and source quality. For each, mark **[REAL] public signal** vs **[HYPOTHESIS] inferred buyer**. Public pricing is market context, not a qualified lead.
3. **Deliverable:** With permission or on an owned/synthetic test site, use existing `skills/build-web-page/SKILL.md` and browser tools to implement exactly one improvement. Record before, after, test and regression check. Prepare a plain-language acceptance report.
4. **Sales validation:** Show a nonbinding pilot proposal to 5 suitable contacts using operator-approved, lawfully sourced channels. Record contact, response, opt-out and buyer objection as facts; no autonomous bulk send.
5. **Product validation:** Recruit 10 willing testers for JACO CODE only after clean install, authenticated tool/use test and a real local task receipt. Track funnel separately from service customers.
6. **Economics:** Capture actual paid invoices, settled payments, refunds, direct variable costs and human hours separately. Zero unverified sales. Compare unit contribution per delivery.
7. **Learning:** Store validated outcome and failure evidence in Continuum; improve the existing skill/offer rather than spawning a parallel system.

## Pilot acceptance
- One external customer's explicitly accepted bounded task, tested delivery, customer sign-off and independent proof of settled payment; positive contribution after recorded costs.
- Separately: JACO CODE can complete a reproducible start-to-receipt user journey and recruit 10 qualified external testers.
- **Stop / revise** if 5 qualified buyer conversations reveal no urgent paid problem; do not optimize a landing page instead of listening.
- New expenses, credentials, client production writes and public launch require explicit operator approval. Initial paid cloud budget **USD 0** until separately configured and observed.
